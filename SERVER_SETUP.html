Server Setup Tutorial

Step-by-step guide to deploying the 3D Gaussian Splatting processing server and using it from your iPhone — no app install required.

How it works: You run a Linux server (or cloud VM) with Docker. The server hosts a web page you open on your iPhone — upload a video, watch training progress, then view and download the finished 3D scene. No app to install.

1

What You Need — Hardware & Prerequisites

Component Minimum MIN Recommended REC Notes
GPU CPU only (slow) NVIDIA RTX 3090 / 4090 GPU training is 20–50× faster. CPU is viable for testing.
VRAM — 16 GB+ Large scenes need more VRAM.
RAM 8 GB 32 GB COLMAP reconstruction is memory-intensive.
Disk 40 GB free 200 GB SSD Docker images ≈ 20 GB; each job ≈ 5–15 GB.
OS Ubuntu 22.04 LTS (or 24.04) Other Linux distros work; adjust package manager commands.
Network Local network (Wi-Fi/Ethernet) iPhone and server must be on the same Wi-Fi, or use a VPN / port forward for remote access.
⚠️

Cloud VMs: AWS g4dn.xlarge, g5.xlarge or GCP n1-standard-4 + T4 all work. Make sure to open port 80 in the security group / firewall so your iPhone can reach the server.

Software you need on the server

  • Git — to clone the repo
  • Docker Engine + Docker Compose v2 — runs all services
  • NVIDIA Container Toolkit — only if you have an NVIDIA GPU

Everything else (COLMAP, FFmpeg, Nerfstudio, Python, Nginx) is inside Docker — you do not install it on the host.

2

Install Docker & NVIDIA Container Toolkit

Step 2.1

Install Docker Engine

Run these commands on your Ubuntu server (copy the whole block):

# Remove any old Docker versions
sudo apt-get remove -y docker docker-engine docker.io containerd runc 2>/dev/null || true

# Add Docker's official GPG key and repository
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Install Docker Engine + Compose plugin
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io \
  docker-buildx-plugin docker-compose-plugin
Step 2.2

Allow your user to run Docker without sudo

sudo usermod -aG docker $USER
# Log out and back in (or run the next line to apply immediately):
newgrp docker

Verify with: docker run hello-world

Step 2.3 — GPU servers only

Install NVIDIA Container Toolkit

⚠️

Skip this step entirely if you have no NVIDIA GPU. The server will use CPU instead (training takes several hours instead of minutes).

First, make sure the NVIDIA driver is installed:

nvidia-smi   # should print your GPU model and driver version

Then install the Container Toolkit:

curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey \
  | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg

curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list \
  | sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' \
  | sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list

sudo apt-get update
sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker

Verify:

docker run --rm --gpus all nvidia/cuda:12.1.0-base-ubuntu22.04 nvidia-smi

You should see your GPU listed inside the container output.

3

Clone the Repository

Step 3.1

Install Git and clone

sudo apt-get install -y git
git clone https://github.com/claws02/walkthrough.git ScanCapture
cd ScanCapture
📁

Your working directory is now ~/ScanCapture. All remaining commands in this tutorial assume you are inside this directory.

4

Configure the Environment

Step 4.1

Create the backend .env file

cp backend/.env.example backend/.env
Step 4.2

Edit settings (optional but recommended)

Open the file with any editor:

nano backend/.env

The key settings you may want to change:

VariableDefaultWhen to change
NERFSTUDIO_MAX_ITERATIONS 30000 Lower to 7000–15000 for faster (lower quality) results. Raise to 50000 for highest quality.
MAX_UPLOAD_SIZE_MB 1024 Increase if you upload very long videos (e.g. 2048 for ~2 GB).
COLMAP_USE_GPU 0 Set to 1 if you have an NVIDIA GPU and installed the Container Toolkit above.
COLMAP_GPU_INDEX 0 Leave at 0 for single-GPU setups.

Save and exit: press Ctrl+O, then Enter, then Ctrl+X.

5

Build & Start the Server

⏱️

First-time build takes 20–40 minutes. Docker downloads and compiles the Nerfstudio + COLMAP images. Subsequent starts are instant — the images are cached.

Step 5.1

Build all Docker images

cd backend
docker compose build

You will see many lines of output as Docker downloads base images and installs packages. This is normal. Wait for it to finish.

Step 5.2

Start the server in the background

docker compose up -d

The -d flag runs everything as background daemons. You will see four services start:

  • redis — job queue
  • api — FastAPI REST server
  • worker — Celery worker (runs COLMAP + Nerfstudio)
  • nginx — reverse proxy, serves the web UI on port 80
Step 5.3

Verify everything is running

docker compose ps

All four services should show Up or running status. If any show Exit, check the logs (see Section 8).

# Quick health check:
curl http://localhost/health

Expected response: {"status":"ok"}

✅

The server is now running. It will restart automatically after reboots because Docker Compose uses restart: unless-stopped by default.

6

Find Your Server IP

Step 6.1

Get your local network IP

hostname -I | awk '{print $1}'

This prints something like 192.168.1.42. That is the address you type into your iPhone's browser.

Alternatively, run:

ip addr show | grep "inet " | grep -v 127.0.0.1
🌐

Cloud VMs: Use the VM's public IP address instead. Make sure port 80 (HTTP) is open in your cloud provider's security group or firewall rules. On AWS: EC2 → Security Groups → Edit Inbound Rules → Add HTTP (port 80) from 0.0.0.0/0.

🔒

No HTTPS by default. The server uses plain HTTP on port 80. This is fine on a trusted local network. For internet-facing deployments, consider adding a reverse proxy with Let's Encrypt (Certbot + nginx).

7

Use the App from Your iPhone

Step 7.1

Open the web interface

On your iPhone, open Safari and navigate to:

http://<YOUR-SERVER-IP>

Example: http://192.168.1.42

You will see the ScanCapture 3D upload interface.

Step 7.2

Record a video on your iPhone

  • Use the built-in Camera app — regular video mode works.
  • Walk slowly around your subject (object, room, outdoor scene).
  • Keep the subject in frame; overlap each position by ~70%.
  • Aim for 30–120 seconds of footage. Longer is not always better.
  • Good lighting is the single most important factor — avoid harsh shadows.
  • Supported formats: MP4, MOV, AVI, MKV, M4V, WebM. iPhone Camera produces .MOV — that works perfectly.
Step 7.3

Upload the video

  1. Tap "Select File" in the web interface.
  2. Choose Photo Library → select your video.
  3. Tap "Upload & Process".
  4. A progress bar appears. Upload speed depends on your Wi-Fi.
Step 7.4

Wait for processing

After upload, the job goes through three stages. You can leave the page — tap refresh any time to check status.

StageWhat happensTypical time (GPU)CPU only
Extracting framesFFmpeg extracts ~150 frames from your video~30 sec~30 sec
Running COLMAPEstimates camera positions from the frames2–10 min10–30 min
Training 3DGSNerfstudio trains the Gaussian Splat model15–40 min3–8 hours
Step 7.5

View and download your 3D scene

When the job shows Done, two buttons appear:

  • View 3D — opens the interactive WebGL viewer directly in Safari. Drag to orbit, pinch to zoom.
  • Download .ply — saves the point-cloud file to your iPhone for use in other apps.
🎉

That's it! No app to install, no Xcode, no developer account. Just Safari and your Wi-Fi connection.

Managing the Server (Start / Stop / Logs)

All commands run from inside the backend/ directory:

Start / Stop / Restart

# Start (or restart after a reboot)
docker compose up -d

# Stop all services (preserves data)
docker compose down

# Restart a single service (e.g. after config change)
docker compose restart api
View logs

# Live logs from all services (Ctrl+C to stop)
docker compose logs -f

# Logs from one service only
docker compose logs -f worker
docker compose logs -f api

# Last 100 lines, no live follow
docker compose logs --tail=100 worker
Disk usage & cleanup

# How much space are job results using?
du -sh /var/lib/docker/volumes/backend_scan_data

# Delete a specific job's files (replace JOB_ID):
# (Find job IDs in the web interface or via the API)

# Remove all stopped containers and dangling images (safe to run):
docker system prune -f
Rebuild after a code update

git pull
docker compose build
docker compose up -d
API reference

The interactive API documentation is available at:

http://<YOUR-SERVER-IP>/api/docs

Troubleshooting

Click a problem to expand the answer.

I can't reach the server from my iPhone (connection refused / timeout) ›

1. Check all containers are running:

cd backend && docker compose ps

If nginx is not running, check its logs: docker compose logs nginx

2. Verify port 80 is listening:

ss -tlnp | grep ':80'

3. Check the firewall:

sudo ufw status
# If active and port 80 is not listed:
sudo ufw allow 80/tcp

4. Make sure your iPhone is on the same Wi-Fi network as the server. Or, if using a cloud VM, ensure port 80 is open in the cloud firewall / security group.

A container shows "Exit" status or won't start ›

Check the logs for the failing service:

docker compose logs api     # or worker, redis, nginx

Common causes:

  • Port 80 already in use: Another web server is running. Stop it: sudo systemctl stop apache2 nginx
  • Out of disk space: df -h / — free space if needed.
  • Missing .env file: cp backend/.env.example backend/.env
Upload fails with "413 Request Entity Too Large" ›

Your video is larger than the configured upload limit. Edit backend/.env and increase:

MAX_UPLOAD_SIZE_MB=2048

Then restart the API:

cd backend && docker compose restart api
Job is stuck at "processing" for a very long time ›

Check what the worker is doing:

docker compose logs -f worker

Common causes:

  • COLMAP running on CPU: This is normal — CPU COLMAP can take 30+ minutes. Check if COLMAP_USE_GPU=1 is set (requires NVIDIA Container Toolkit).
  • Training on CPU: Without a GPU, Nerfstudio training takes hours. This is expected.
  • Worker crashed: Look for ERROR or Traceback in the logs. Restart with docker compose restart worker.
Job fails with "not enough frames" or "COLMAP failed to reconstruct" ›

COLMAP needs enough visual overlap between frames to triangulate camera positions.

  • Move more slowly when recording — fast movement blurs frames.
  • Overlap more — each step should cover ~70% of the previous frame.
  • Use better lighting — dark or flat-lit scenes have few distinguishable features.
  • Avoid reflective or transparent surfaces — glass, mirrors, and shiny floors confuse COLMAP.
  • Make the video longer — aim for at least 30 seconds walking around the subject.
The 3D viewer shows nothing or a black screen ›

The viewer requires WebGL 2, which Safari on iOS 15+ supports.

  • Make sure your iPhone is running iOS 15 or later.
  • Try reloading the page — the first load can be slow for large files.
  • If the .ply file is large (200+ MB), it may take 10–30 seconds to parse on mobile. Wait for the loading indicator to disappear.
  • Check the browser console for errors: on iOS, connect to Safari on a Mac and use Web Inspector.
GPU is not being used even though I have an NVIDIA card ›

Two things must both be true:

  1. The NVIDIA Container Toolkit is installed and the Docker runtime is configured (Section 2.3).
  2. COLMAP_USE_GPU=1 is set in backend/.env.

Verify GPU is accessible in Docker:

docker run --rm --gpus all nvidia/cuda:12.1.0-base-ubuntu22.04 nvidia-smi

After changing .env, restart the worker:

cd backend && docker compose restart worker
How do I free up disk space from old jobs? ›

Delete jobs through the web interface (the trash icon next to each job). This calls the API which removes the files and database record.

To manually inspect the data volume:

docker run --rm -v backend_scan_data:/data alpine ls -lh /data/results/

To delete everything and start fresh (destructive!):

cd backend
docker compose down
docker volume rm backend_scan_data
docker compose up -d
